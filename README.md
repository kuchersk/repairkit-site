# Repairkit · Склад — автономный сайт

Полностью самостоятельное веб-приложение: сканирование штрихкодов, номенклатура,
загрузка остатков, учёт заказов по маркетплейсам. Никаких зависимостей от
claude.ai — свой backend (FastAPI) и своя база (SQLite), фронтенд отдаётся
тем же сервером.

## Структура

```
repairkit-site/
├── docker-compose.yml      ← разворачивать этим файлом (в т.ч. через Coolify)
├── .env.example            ← скопировать в .env и задать APP_API_KEY
└── backend/
    ├── main.py              ← backend (FastAPI)
    ├── requirements.txt
    ├── Dockerfile
    ├── data/
    │   └── seed_items.json  ← начальная номенклатура (1349 позиций), грузится один раз при первом старте
    └── static/
        ├── index.html        ← весь фронтенд (один файл)
        └── manifest.webmanifest
```

## Деплой через Coolify (тот же сервер, что и бот)

1. Залейте эту папку в git-репозиторий (или новый, или отдельную ветку/подпапку в существующем).
2. В Coolify: New Resource → Docker Compose → укажите репозиторий и путь к `docker-compose.yml`.
3. Задайте переменную окружения `APP_API_KEY` — придумайте длинную случайную строку
   (например `openssl rand -hex 24`). **Обязательно сделайте это до того, как сайт
   станет доступен из интернета** — иначе кто угодно сможет менять ваши остатки.
4. Разверните. Coolify выдаст домен (или привяжите свой, например `sklad.repairkit...`).
5. Откройте сайт → нажмите ⚙ в шапке → вставьте тот же ключ, что в `APP_API_KEY`.
   Это нужно сделать один раз на каждом устройстве/браузере, который будет сканировать.

При первом запуске backend сам загрузит номенклатуру из `data/seed_items.json`
(1349 позиций с текущими остатками) — ничего вручную грузить не нужно.

## Данные и бэкапы

Вся база — один файл `data/repairkit.db` (SQLite) внутри volume `repairkit_data`.
Не забудьте настроить бэкап этого volume на вашем сервере (Coolify это умеет из коробки
для volume-ов, либо простой cron с `sqlite3 .backup`).

## Как обновлять код дальше

Это уже не claude.ai-артефакт с кнопкой «опубликовать» — обновления теперь
приходят как файлы (я меняю `main.py` / `index.html` и отдаю вам), и дальше
обычный цикл: закоммитить → Coolify пересоберёт и передеплоит контейнер.
Данные (номенклатура, остатки, заказы) при этом не теряются — они в volume,
отдельно от кода.

## Локальный запуск для проверки

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
# открыть http://127.0.0.1:8000
```

## API (если пригодится для бота/интеграций)

- `GET /api/items` — вся номенклатура
- `PUT /api/items/{sku}` — создать/обновить позицию (остаток не трогает, если позиция уже есть)
- `POST /api/items/{sku}/stock` — `{"delta": 5}` прибавить/списать, либо `{"stock": 20}` выставить абсолютно
- `GET /api/orders`, `POST /api/orders`, `DELETE /api/orders/{id}` — загрузки заказов по маркетплейсам

Все запросы (кроме `GET /`) ожидают заголовок `X-API-Key`, если `APP_API_KEY` задан.
